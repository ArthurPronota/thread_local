# Описание: `thread_local!` в Rust на основе примера

## Что демонстрирует код

Пример показывает, как с помощью макроса `thread_local!` создать **статическую переменную, локальную для каждого потока** (Thread-Local Storage, TLS). Каждый поток получает **собственную независимую копию** переменной, и изменения в одном потоке не влияют на другие.

## Ключевой элемент — `thread_local!`

### Синтаксис

```rust
thread_local! {
    static COUNTER: RefCell<u64> = RefCell::new(0);
}
```

Макрос `thread_local!` оборачивает одно или несколько статических объявлений и делает их локальными для потока. При этом:

- допускается указывать видимость (`pub`, `pub(crate)` и т.д.);
- допускается указывать атрибуты для каждого `static`;
- каждый поток получает **свою копию** значения.

### Что происходит «под капотом»

- Для каждого потока создаётся отдельный экземпляр переменной `COUNTER`.
- Значение инициализируется **лениво** — при первом обращении через `.with(...)`.
- Когда поток завершается, его копия TLS-переменной уничтожается.

## Доступ к значению: `.with(...)`

TLS-переменные нельзя использовать напрямую — к ним обращаются через метод `.with()`:

```rust
COUNTER.with(|c| {
    *c.borrow_mut() += 1;
})
```

- `.with()` принимает замыкание, которому передаётся ссылка на значение.
- Замыкание выполняется **в контексте текущего потока**.
- Если значение ещё не инициализировано, оно инициализируется прямо здесь.

## Зачем нужен `RefCell`

TLS-переменные в Rust требуют, чтобы тип значения был `'static`, но при этом нужно иметь возможность **менять** его из `&self`-контекста замыкания. Поэтому используется `RefCell<u64>`:

- `RefCell` обеспечивает **внутреннюю изменяемость** (interior mutability).
- Проверки заимствования выполняются **во время выполнения**, а не во время компиляции.
- `borrow_mut()` даёт изменяемую ссылку, `borrow()` — неизменяемую.

Важно: `RefCell` не потокобезопасен, но это и не нужно — каждый поток работает со **своей** копией, поэтому гонок данных нет.

## Функции `my_incr` и `my_get`

```rust
fn my_incr() {
    COUNTER.with(|c| {
        *c.borrow_mut() += 1;
    })
}

fn my_get() -> u64 {
    COUNTER.with(|c| {
        *c.borrow()
    })
}
```

- `my_incr` увеличивает локальный счётчик на 1.
- `my_get` возвращает текущее значение локального счётчика.
- Обе функции работают с **TLS-переменной текущего потока**.

## Что делает `main`

```rust
let handle: Vec<_> = (0..3)
    .map(|ind| {
        thread::spawn(move || {
            my_incr();
            my_incr();
            println!("Thread: {ind}, val: {}", my_get());
        })
    })
    .collect();
```

Создаются **три потока**. Каждый поток:

1. Увеличивает **свой** счётчик дважды (`my_incr()` вызывается два раза).
2. Печатает `Thread: <индекс>, val: <значение>` — ожидается `val: 2`.
3. Завершается, и его TLS-копия `COUNTER` уничтожается.

Затем:

```rust
for h in handle {
    h.join().unwrap();
}

println!("Local thread, val: {}", my_get());
```

- Главный поток дожидается завершения всех трёх.
- В **главном потоке** `COUNTER` — это **отдельная** копия, которая инициализируется при первом вызове `my_get()`.
- Главный поток **никогда не вызывал** `my_incr()`, поэтому его счётчик равен `0`.

## Ожидаемый вывод

Порядок строк от потоков может варьироваться (потоки выполняются параллельно), но значения всегда одинаковы:

```
Thread: 0, val: 2
Thread: 1, val: 2
Thread: 2, val: 2
Local thread, val: 0
```

## Главный вывод

| Свойство | Поведение |
|---|---|
| Копия переменной | Своя у каждого потока |
| Изоляция | Изменения не видны другим потокам |
| Инициализация | Ленивая, при первом `.with(...)` |
| Время жизни | До завершения потока |
| Доступ | Только через `.with(...)` |
| Изменяемость | Обеспечивается `RefCell` |
| Потокобезопасность | Не нужна — данные не разделяются |

`thread_local!` — это инструмент для случаев, когда нужно **состояние, привязанное к потоку**: счётчики, буферы, кэши, контекст выполнения — всё, что не должно разделяться между потоками и не требует синхронизации.
